# 当前架构

版本 3.52；核对日期 2026-09-18。依据真实入口、导入、接口、流程与相关验证，不复制历史检查报告，不以文件数量为主体。当前代码目录未重排。

## 运行入口和核心装配

`streamlit run 启动程序.py` 导入 `软件界面/主界面.py::运行主界面`；页面导航包括候选、用户导入、身份审核、化学信息、规则筛选、配方构建、配方发现与验证、透明化预测、实验记录、实验优化与毒性评估。页面现有旧演示版文案未修改，README 的当前版本依据用户的 3.51 版本目录工作方式。

`运行配方研发.py` 提供验证/发现命令入口。发现需明确 JSON 候选库或显式试跑演示库；调用核心研发流程，并自动创建根 `运行记录/配方研发_*` 保存 JSON/Markdown 报告。历史根运行输出已清理，计算输入库保留。

`创建颅骨透明化筛选流程控制器(Path)` 创建运行数据管理器、插件管理器并显式注册当前插件。插件管理器只查找，不负责业务编排。Python 入口还包括 `运行颅骨透明化流程`、`预测完整配方`、`运行验证模式`、`运行发现模式`。

## 主要流程与数据流

### 用户筛选与论文参考

用户文件/字段映射/应用规则 → 控制器创建 run_id → 通用候选导入 → 身份转换 → RDKit 结构/描述符 → 用户 HSP 初筛 → 通用规则 → 报告。激活运行后产物进入 `数据/运行记录/<run_id>/`；软件数据库仍全局。通用规则有属性/规则注册和应用配置，但用户 HSP 前置计算仍使用现有 SeeThrough 参照，不应声称整个链完全用途无关。

补充数据3流程做论文导入、结构、描述符、Hansen、合并；补充数据2流程做清理/数值规则、身份/结构/描述符/Hansen、自动规则、合并/冲突、公开危险提示/毒性视图、报告及可选图表。论文最终10标签在自动筛选后对照，不参与自动选择。没有激活 run_id 的旧流程仍使用固定结果目录。

### 确认批次与当前用途

运行候选 → 跨运行工作草稿（来源运行、成分键、浓度/单位） → 明确确认 → 批次快照/全局目录 → 自动描述符与用途评估。`化合物确认清单.py` 管该状态流；当前草稿确认仍限制为颅骨透明化，不是公共层长期假设。

`配方评估流程.py` 编排可选完整配方组装、用途配置、成分 RI/水合、HSP 比较、物性汇总、配方摘要、实验终点、特征和用途约束。`颅骨透明化用途.py` 负责批次读取/保存，并追加描述符筛选近似；同批次结果更新覆盖，不是不可变模型运行历史。

用途读取五类统一物性，组织有效扩散、局部滞留、washout 和局部/全身毒性保持未知。实验终点录入与特征就绪提示已存在，尚不代表训练、有效预测或下一轮优化建议。

### 配方研发

核心研发流程分验证与发现：验证从设置读取已知体系，检查数值链、参考误差与固体 eRI 边界；发现先做合成数值接口自检，再由独立来源库进行分子筛选 → 有限质量分数网格组合 → 完整组装 → 物性/约束评价 → Pareto 排序 → 前沿局部细化与再评价，最后附上已知体系对照。搜索门禁是数值自检，不要求先通过 Benchmark。

发现池默认不自动加载，主溶剂按相态/比例选择，不强制固定名字。输入来源、条件、警告、排除和失败定义保留。TD-01 已修复：局部细化读取组装后规范化质量分数，质量转移保持总和 1 和各项正值，经现有组装定义重新评价。默认内存演示粗搜 52、累计定义及排序 65、组装失败 0；不代表全局最优。

带目标规格时先编译并预检，失败不启动自检/组合搜索；分子硬约束先筛池，配方物性仍经过现有完整预测，再由现有约束插件评价、现有排序插件 Pareto 排序和局部再评价。规格所需物性决定自检要求；无 Profile objectives 时仍要求 legacy RI+黏度。report_only 缺失不影响资格；完整预测保持原有行为，disabled 不增加模型要求。全部 criterion 值/单位/来源/状态和判断随结果保留，Benchmark 最后加载。CLI 可用 `--target-profile <json>` 经正式 load_profile 接入，UI 未改。

### 公开证据：现有可替换模式

控制器独立公开查询 → `公开证据聚合插件` → ProviderRegistry 注册的 PublicDataProvider → 来源 client/raw cache/parser → EvidenceRepository 独立长表 → EvidenceRequest / EvidenceResolver → ResolvedProperty 与查询日志。

`核心系统/公开证据/` 提供 Provider/Repository 及身份/证据/请求/结果契约、注册、条件匹配、单位/身份标准化和冲突解析。没有导入具体 Provider。PubChem、CompTox、NIST、ThermoML 具体实现在 `插件/公开数据/providers/`，彼此不互相查询，通过统一接口注册。

新入口默认 DuckDB，支持 SQLite/Parquet，旧 GHS 外观默认 SQLite；raw cache 独立保存原始响应。可注入来源注册表、Repository、raw cache；Resolver 目前在聚合内部直接构造，没有上下文注入入口。存储内表/分片是内部实现，不是业务契约。

证据保留条件、单位、形式、类型、来源及 raw 关系，冲突不静默覆盖或平均。新公开物性未接旧 descriptor 宽表、配方模型或独立发现池。旧毒理页面公开入口仅支持 PubChem GHS；这不意味着新公开证据系统只有 GHS。CompTox 当前能提供远程领域证据，但不等于本地药代模型或已接旧毒理匹配。

### 配方物性：现有可替换模式

核心流程 → 配方物性汇总功能插件 → 模型注册表选择独立 `预测(配方, 上游)` 策略。模型只负责自己的指标，依赖通过 `依赖指标` 由汇总递归调度，检测环和未注册依赖；不反调功能插件。

当前注册 Lorentz–Lorenz；Grunberg–Nissan、Cheng_2008 甘油–水与理想对数黏度；Stokes–Einstein；理想/系数修正渗透压；理想/系数修正水活度。黏度 auto 按 Grunberg–Nissan、Cheng、理想对数顺序尝试，有效实测始终优先，未知保持状态。用途仅比较输出，底层模型不限定颅骨用途。

### Target Profile 的真实状态

`核心系统/目标规格/` 提供 Criterion/TargetProfile、严格校验、不可变编辑、JSON 存取、纯指标绑定和 ExecutionPlan 编译/预检；不依赖插件、工作流、候选库或 Benchmark。Execution v1 已接核心发现入口/CLI、现有分子筛选、配方约束和唯一 Pareto 排序器。支持 formulation 的 refractive_index、viscosity、diffusion_coefficient、osmotic_pressure、water_activity、cost；molecule 的 molecular_weight 仅支持硬约束/报告。

未绑定指标、delivery/experiment、molecule objective、数值绑定的布尔 equals、单位不兼容及不满足的证据要求明确预检失败。五类物性区分已预测/已实测；发现流程无实测输入，measured_only 失败。成本为 derived、分子量未标明 measured/predicted，仅允许 any 且值必须有来源。UI 和公开证据层全面连接仍未实现；未增加 pKa、logD、ADMET、结构搜索、HSP Sphere 或 Agent。

## 关键职责、依赖与注册表

核心负责流程与公共契约；插件负责分类功能及来源/模型策略；设置负责配置和显式参考；数据负责原件与产物；界面负责输入展示；测试保留回归及冻结外部评估。只有本目录维护内部说明正文。详见 `02`、`03`。

已存在功能插件注册、ProviderRegistry、属性/规则注册与应用配置、物性模型注册；已有获取插件回调、模型注册表与来源/存储/缓存注入扩展。研发生成/约束/排序插件仍直接实例化，不能声称全平台已经动态可替换。

允许入口/界面调用核心公开流程，核心按公共契约装配实现；插件依赖共用契约与自身策略。底层不依赖 UI、Agent 或具体研究计划。现存私有调用、插件内部函数依赖、页面直接调用插件及用途绑定如实记录在 `07`；不将其视为正常新增方式。

## 兼容与未启用项

`创建补充数据3流程控制器` 是现工厂别名；插件标识 `PubChem查询` 指向同一聚合实例；旧 PubChem 类及 CompTox 查询类名是兼容外观，CompTox 旧报告插件仅显示配置状态。旧用途运行器反向转发核心用途流程；数据管理无运行时回退旧目录，最终结果先模型后筛选。

GP、BoTorch、候选评分和独立官能团功能插件未启用；RDKit 已有自己的 SMARTS 描述符分类，并不因此启用独立官能团插件。统一预测/优化抽象接口、纯注释配置、人体口服信息视图/代谢字段和外部测试药代规格是不同类别，见 `07`。当前没有训练产物、递送模块或 Agent。
