# 接口与数据契约

当前契约依实际代码记录；公开接口与内部实现区分如下。模块详见 [公开证据层](模块/公开证据层.md)、[Target Profile](模块/Target_Profile.md)、[配方物性](模块/配方物性.md)。

## 功能插件、注册与上下文

`插件/插件接口.py` 的 `基础插件接口` 提供 `插件标识` 与抽象 `执行(数据上下文: Any) -> Any`。实际结果可为 DataFrame、字典、元组或 Path，不存在已实现的统一消息容器。`未启用插件` 只返回状态，不生成虚构结果。

`核心系统/插件管理器.py` 公开 `注册插件(插件标识, 插件实例)`、`获取插件(插件标识)`。当前注册不校验实例且同标识覆盖；未知标识抛 KeyError；内部 `_已注册插件` 不对其他模块开放。它不是自动发现、依赖调度或生命周期框架。

用户筛选上下文主要含数据管理器、文件名/bytes、字段映射、应用配置/用户设置和运行编号。用途上下文主要含成分、用途配置、HSP参照、配方设置、实验记录、配方编号；物性选择/条件/参数有明确键。研发输入为物质记录列表、配方定义/生成配置、约束和配方证据。新字段必须在正式上下文说明中声明；不得从页面状态或临时文件猜测。

## 共用记录与文件数据管理

`核心系统/数据格式定义.py` 定义三个 Pydantic 模型：`化学候选记录`（可缺失候选、名称、CAS、来源及现有 RI/水合/pH/Hansen 字段和指定别名）、`数据批次`（批次标识、数据类型、来源、附加信息）、`毒性证据记录`（必填候选编号/终点/实验值或预测值，其他实验条件/来源可缺失）。候选和毒性模型 extra=allow，保留原字段；不等于所有 DataFrame 已强类型化。

`数据管理接口` 公开论文读取，中间/最终/筛选结果读写、软件数据库读取、结果存在检查、导出及用户原件保存；文件实现的读操作返回 DataFrame，保存返回 Path。软件数据库写入和论文目录可写检查目前只在具体 `文件数据访问管理器` 中提供，抽象契约仍有缺口。

论文按 Excel 读取；软件数据库 CSV 按字符串保留空串；结果 CSV 保留空串但可推断列类型；保存 UTF-8 BOM、不写索引。最终结果读取先模型后筛选。内部 `_保存表格/_读取表格`、目录属性和路径拼接不是跨模块通信协议。论文原件写保护不等于全面路径沙箱。

`运行数据管理器` 公开创建/激活运行、运行目录/当前编号及带可选 run_id 的读写；激活后产物进入 `数据/运行记录/<run_id>/`，否则兼容旧结果位置。软件数据库/确认目录仍全局。固定结果标识是现有兼容约定，新开发不能引入临时 CSV 总线。

候选编号在运行内标识行；跨运行保留 run_id，确认批次保留批次编号、来源和成分键。全局公开 compound_id 应稳定地区分化学形式，不将本地行号当全局化合物身份。

## 公开证据正式接口

| 公共接口/结构 | 当前能力 |
| --- | --- |
| `PublicDataProvider` | capabilities、resolve_identity、fetch_properties；hazard/bioactivity/toxicokinetics 默认 unsupported，可由来源实现 |
| `ProviderRegistry` | register/get/providers；重复 provider_id 拒绝；通过接口注册替换来源 |
| `CompoundIdentity` | 稳定 compound_id、observed/parent 结构、形式、InChIKey、来源标识与标准化版本 |
| `PropertyEvidence` | 值/单位/界限/条件/形式/类型/方法/模型/来源/文献/抓取/解析/raw 关系和原始 extra；类型为 measured/predicted/derived/summary |
| `EvidenceRequest` | 请求身份/属性、形式/结构、温度/pH/压力等条件及容差、来源、measured_only、未知条件策略 |
| `ResolvedProperty` | request/status/selected/evidence_ids/conflicts/reason；不是丢弃出处的裸数值 |
| `ProviderResult` | 状态、证据 tuple、身份、消息、raw IDs 和缓存命中 |
| `EvidenceRepository` | add(evidence)、query(compound_id/property_id/sources/temperature_range)、close 和上下文管理 |
| `EvidenceResolver` | resolve(request, evidence)，条件/单位标准化后形成采用、missing 或 conflict |

公共条件匹配、单位标准化、身份标准化和冲突解析位于核心证据目录，不依赖具体 Provider。具体来源位于 `插件/公开数据/providers/`，client/parser/mapping/provider 属来源实现，不是别的 Provider 的可调用业务接口。

Repository 当前有 SQLite、DuckDB、Parquet 实现；connection、SQL 表/索引、Parquet payload 与分片布局属于内部，业务只访问 Repository/Resolver 和聚合返回结构。DuckDB 的 export_parquet 是显式后端扩展，不要求使用证据的模块知道它的内部表。

控制器公开查询通过聚合插件；上下文可注入 `数据源注册表`、`证据存储`、`原始响应缓存`，调用方关闭注入资源。Resolver 当前在聚合内部直接构造，没有同名上下文注入槽；不能把 Provider/Repository 可注入扩大为所有部件均已可注入。

公开证据不覆盖/平均；不同条件、形式和类型保持独立，限定值/未解析原文不当确定值；未知请求条件不自动匹配。公开证据输出不直接进入原 descriptor 宽表或配方模型。raw cache 的 SQLite 布局是缓存内部实现，其他模块不读表。

## Target Profile

`核心系统/目标规格/` 公开 Criterion、TargetProfile、ProfileValidationError、import/export_profile_json、save/load_profile。指标 role 为 hard_constraint/objective/report_only/disabled，目标 mode 为 minimize/maximize/target/range；支持 scope 和缺失/证据要求校验。

结构只保存规格，不保存候选、实验、Benchmark 或模型参数；独立于插件/工作流。JSON 拒绝未知/重复字段、非法数值和枚举；编辑返回新对象，保存显式路径且默认拒覆盖。代码允许 molecule/formulation/delivery/experiment scope，后两个当前没有执行绑定。

`指标绑定.py` 的 MetricBinding 声明 scope、来源字段、标准单位、证据类型能力及可执行 role；`执行计划.py::compile_profile(profile, legacy_constraints=..., available_properties=..., model_selection=...)` 返回不可变 ExecutionPlan 和可导出的预检结果，不执行模型或查询。scope 省略时由绑定明确确定；显式 unit 必须与标准单位相同，不猜测或隐式换算。数值绑定不接受布尔 equals 执行，契约本身仍保留 equals。

`运行发现模式(..., 目标规格=None)` 接受正式 TargetProfile；流程将 ExecutionPlan 通过插件上下文 `执行计划` 传给现有分子筛选、配方约束及候选排序。结果保留原始规格/version、计划、预检、全部配方评价、排除分子评价及最终 objectives；每条 `目标规格评价` 含原始值/单位、合格值、状态、缺失原因、role、来源/类型/条件和硬判断或目标变换。molecule 结果按物质保留，不隐式聚合为配方 objective。

规格硬约束使用各 criterion 的 missing_policy，独立于 legacy 全局缺失策略；两者取 AND，直接数值冲突在预检报错。Profile objectives 优先，否则使用 legacy 优化目标/默认 RI+黏度。目标缺失 keep_unknown 保留在 `未知未排序候选`，exclude 取消可排序资格，两者均不伪造向量。只有 objective 进入 Pareto；report_only 不影响资格或向量，disabled 不进入执行要求。目标变换为 value、-value、abs(value-target)、区间外距离/区间内零；tolerance 不自动变成硬约束。

## 配方与物性契约

完整组装含 `配方定义`（物质编号、用量、单位、角色）、`物质库`（唯一编号、分子量及所需物性/来源）、`物性条件`。分数同基准且和为 1；绝对量支持 g/mg/mL/uL/mol/mmol，按体积需匹配温度的密度。输出质量、摩尔、纯组分等效体积分数和显式体积依据，不补溶剂，不用固体 eRI 补液体 RI。返回定义可能已经换为绝对用量；比例细化必须读取 `成分[*].质量分数` 与 `成分键`，用现有 `组装定义` 生成规范化质量分数定义，与粗搜 `已有签名` 比较。

物性正式接口为 `配方输入`、`物性结果`、`物性模型接口.预测(配方, 上游)`、`模型注册表` 与 `配方物性汇总插件.执行`。结果保留值/单位/状态/方法/版本/来源/适用范围/警告/置信度/不确定度/依赖。标准单位为 RI/水活度无量纲、黏度 mPa·s、扩散 m²/s、渗透压 Pa。

新增模型继承现有指标接口、声明方法/版本/单位/适用范围及依赖，注册并配置选择；汇总根据声明计算上游，检测循环，不让策略反调功能插件。实测优先，无效已填实测不静默换预测；缺数据用输入不可用，auto 保留回退原因，未量化置信度/区间保持 None。

## 其他重要边界

通用规则引擎使用属性定义/记录、规则定义/注册与应用配置，按 run_id/候选编号/属性编号关联；它不读公开库内部表。毒理会话区分指定、不作为条件和未知，匹配结果保留证据与缺口，GHS 不参与 A/B/C/D 实验条件匹配。

统一预测与优化抽象接口是合理扩展点，具体 GP/BoTorch 当前未启用。用途兼容运行器、PubChem/CompTox 旧导入名只保留现有行为，不据此建设第二条流程。其他私有调用、场景绑定及历史标识债务见 `07`，本轮不顺手修复。
