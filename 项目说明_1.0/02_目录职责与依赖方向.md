# 目录职责与依赖方向

依据当前真实布局，不重新设计代码目录。当前根目录是独立完整版本；版本复制方式保持原样。

## 放置与访问规则

| 现有位置 | 应该放什么 | 不应该放什么 |
| --- | --- | --- |
| 根目录 | `启动程序.py`、`运行配方研发.py`、依赖/工程声明、README 与许可入口 | 新代码外壳、散落的业务实现、内部设计副本或科研计划需求 |
| `核心系统/` | 插件装配与流程编排、共用数据管理、校验、规则引擎、确认批次/用途存取 | UI 交互、具体外部数据库 Provider、Agent 依赖 |
| `核心系统/公开证据/` | Provider/Repository/身份/证据/请求契约、Resolver、条件/单位/身份标准化与冲突解析 | 具体 Provider、依赖某来源内部字段的业务调用 |
| `核心系统/目标规格/` | Target Profile 数据校验、不可变编辑、JSON 存取、纯指标绑定及执行计划编译/预检 | 查询候选库/Benchmark、执行模型、UI 或跨模块调度 |
| `插件/数据导入/`、`数据合并/` | 导入与身份适配、属性合并/冲突检测 | 另一套公开来源查询系统或上层业务编排 |
| `插件/化学计算/`、`筛选与评价/` | 化学计算、规则/证据评价、特征与报告 | 对其他功能插件私有实现的隐藏调用 |
| `插件/公开数据/` | 公开聚合功能入口、兼容转换与缓存迁移；`providers/<来源>/` 按 client/parser/mapping/provider 分工放置具体实现 | Provider 互调、直接改 UI、覆盖 descriptor 宽表 |
| `插件/配方生成/` | 输入组装、组合生成、比例细化、发现约束、候选排序 | 跨功能搜索循环、Benchmark 泄漏到独立发现池 |
| `插件/配方物性/` | 输入/结果/模型接口、注册与汇总；模型放入折射率/黏度/扩散/渗透/水活度现有分类 | 用途阈值、毒理结论或模型反调功能插件 |
| `插件/颅骨透明化/` | 当前用途配置、成分/配方/终点与约束评价 | 将当前用途假设固化到公共层 |
| `插件/透明化预测/`、`实验优化/`、`结果展示/` | 现有预测/优化接口及其真实实现、可视化 | 将占位声明当已实现能力或伪造预测 |
| `设置/` | 现有配置、显式样例及验证资料 | 为运行补造实验值、把验证标签当候选种子 |
| `数据/` | 论文原件、用户原件、软件数据库、各类结果、实验记录和运行隔离数据 | 业务实现、跨模块未经声明的临时通信格式 |
| `软件界面/` | 输入与展示、调用核心公开流程、页面所需状态 | 业务算法、底层依赖的 session state、插件间调度 |
| `测试/` | 回归/流程测试、本地外部评估与冻结参考材料 | 作为新软件需求来源的研究式配置或自动运行的发布任务 |
| `项目说明_1.0/` | 唯一内部说明，`模块/` 仅保存三个正式模块正文 | 第二套架构或旧版本历史堆积 |
| `.venv/` | 本地依赖环境 | 项目实现或新需求 |

根历史运行目录和仅含占位文件的空模型目录已清理。CLI 会自动重新创建根 `运行记录/配方研发_*`；`数据/运行记录/<run_id>/` 是运行隔离数据，本轮保留。没有真实训练模型，此次清理没有删除已启用模型。

## 依赖方向

入口/页面 → 核心公开流程 → 功能插件接口/装配实例。功能插件 → 共用数据契约与存取接口、自身策略。公开聚合 → PublicDataProvider/ProviderRegistry、EvidenceRepository、EvidenceResolver；公共证据层不导入具体 Provider。物性汇总 → 物性模型接口及其声明依赖；策略之间不直接互调。

装配工厂注册具体实现是正常依赖；其他业务模块不得依赖仓库内部数据库结构。当前确有私有调用、页面越界和用途绑定，见 [07](07_技术债与遗留预留.md)，不是允许方向的例外授权。

## 新增与替换文件

先确认职责、正式契约及缺失/单位/来源语义，再进入已有对应分类。新物性模型使用已有指标目录和模型注册表；新来源使用既有 Provider 接口与 `providers/`；跨功能组合进入核心现有流程，不另建平行链。

现有目录能容纳新功能时不增顶级目录；不得创建 `versions/`、`src/`、`app/` 或新的项目外壳。未来上层 Agent 尚未定义，当前不建空目录、接口或框架。
